# 设置指南

CodeHelper 设置页当前包含七个标签：账户、外观、AI 模型、记忆、数据、能力和关于。设置主要写入
本地 SQLite；少量工作区和恢复状态由专用表及 Chromium localStorage 管理。

## 账户

账户页用于编辑本地显示名称和头像，并提供学习记录清理入口。清理学习记录只删除学习活动相关
数据，不会删除题库、知识库、AI 配置、账户资料和课堂笔记。执行前应阅读确认对话框中的实际
范围；需要可逆操作时先创建完整备份。

CodeHelper 当前没有云账户或跨设备同步。这里的账户资料只是本机 profile。

## 外观

外观页提供：

- 明暗模式和跟随系统；
- 多套视觉主题、背景样式和强调色；
- CodeMirror 代码主题；
- 界面字体大小与缩放；
- 动效、桌宠、双行标签、布局和其他显示开关；
- 恢复默认外观。

界面字体大小作用于应用根字号；代码编辑器仍有自己的固定样式和代码主题。旧文档中的
Catppuccin/Fjord/Ember 三主题列表已经不代表当前 UI。

## AI 模型

AI 模型页管理 Provider 配置：

| 字段     | 说明                   |
| -------- | ---------------------- |
| 名称     | 本地显示名称           |
| Base URL | Provider API 基础地址  |
| 模型     | Provider 使用的模型 ID |
| API Key  | 调用 Provider 的凭据   |
| 默认配置 | 未显式选择配置时使用   |
| 任务类型 | 区分聊天等使用场景     |

配置好 Base URL 和 API Key 后可以请求 `/models` 获取模型列表；失败时仍可手动输入模型 ID。
“配置已保存”只表示本地配置存在，不证明网络、账户额度或模型端点当前可用。

### API Key 安全

- 新保存的 API Key 必须通过 Electron `safeStorage` 加密，并以 `enc:` 密文存入 SQLite。
- 如果系统不提供安全凭据存储，或 Linux backend 为 `basic_text`，保存会 fail-closed，不会静默
  写入新的明文 Key。
- Renderer 读取配置时只获得掩码和是否已配置的状态。
- 历史数据库可能仍有无 `enc:` 前缀的兼容数据；应重新保存或轮换这些凭据。
- 完整 `userData` 备份包含 AI 配置密文，但密文可能绑定原系统账户，跨设备恢复后需要重新输入。
- JSON 数据导出当前不包含 `ai_configs` 或 API Key。

不要把数据库、完整备份、API 请求日志或截图上传到公开仓库和问题单。

## 记忆

记忆页管理 AI 对话会使用的本地长期记忆和相关开关。记忆写入 SQLite，可以在 AI 对话发送前
预览实际注入内容。删除或清理操作只影响本地数据，不会撤回已经发送给外部 Provider 的历史
请求。

## 数据

数据页把三种不同的数据保护边界放在同一处：

- **完整数据库备份**：请求所有窗口 flush 后，以 `VACUUM INTO` 创建包含全部已提交 SQLite
  数据的快照。flush、`quick_check` 或写入失败时 fail-closed。
- **备份列表**：显示手动、导入前和迁移前备份的时间、大小、SHA-256 与完整性状态，并可打开
  `<userData>/backups`。
- **导出 JSON**：在单一 SQLite transaction 中读取 10 类受支持表，生成便携数据子集。
- **导入 JSON**：先要求二次确认，再校验版本、32 MB 文件上限和 100,000 条总记录上限；开始
  写入前自动创建 `pre-import` 已验证备份。当前 UI 使用默认 `skip` 冲突策略。
- **导出诊断恢复层**：只允许导出 `codehelper-*` 命名空间中的 `.migration-backup.` 和
  `.corrupt.` localStorage 项；这里不能导入、恢复或删除这些项。

每个数据库快照都有 `.manifest.json`，记录应用版本、应用及组件 schema、文件大小、SHA-256、
创建/验证时间和 `quick_check` 结果。除手动备份外，数据库迁移前也会自动创建
`pre-migration` 备份；备份失败则不开始迁移。

JSON 仍不是完整备份：它不包含编辑器工作区、练习草稿、课程进度、Agent 审计、AI 配置和
localStorage 恢复层。任一导入行错误会使整个 SQLite transaction 回滚，不会保留部分成功结果；
成功导入后仍建议重启并核对业务视图。

应用内数据库快照不包含 localStorage，且仍存放在同一 `userData`。当前版本没有应用内恢复、
备份删除、异地复制或自动选择兼容版本的功能。完整边界和人工恢复步骤见
[数据可移植性](../data-portability.md)与
[备份与恢复手册](../guides/backup-restore-runbook.md)。

## 能力

能力页汇总当前运行环境的可用、降级、不可用和未验证状态：

| 分区     | 展示内容                                                                |
| -------- | ----------------------------------------------------------------------- |
| 运行环境 | 应用版本、平台、是否为打包版本，以及仅有 updater metadata、无应用内更新 |
| 数据库   | `quick_check`、应用/组件 schema、备份目录状态和已登记备份数量           |
| 执行     | 本机语言工具链、Windows Job Host 和 Docker strong-isolation             |
| 知识     | 当前检索模式、后端、索引文档与片段规模、降级原因                        |
| Agent    | 工具白名单、逐次审批、Provider 阻塞和审计能力                           |
| AI       | 配置数量、默认配置、`safeStorage` 状态和连通性检查边界                  |

能力页支持强制刷新。它会探测数据库、工具链和 Docker 等本机状态，但不会自动向 AI Provider 发起
连通性请求；“已配置”和“连通性未检查”是不同状态。实际工作流中的工具链、知识和 Agent 状态仍是
执行当次操作时的最终依据。

## 关于

关于页显示：

- CodeHelper 应用版本；
- Electron、Chrome 和 Node.js 版本；
- 操作系统和架构。

这些信息适合随故障报告一起提供，但不要附带 API Key、完整数据库、代码正文或用户目录截图。

## 工作流状态的位置

统一能力页之外，相关工作流仍展示更贴近当前操作的状态：

| 能力           | 查看位置                 | 说明                                           |
| -------------- | ------------------------ | ---------------------------------------------- |
| 本机语言工具链 | 工作台底部状态栏         | 显示 ready、degraded 或 missing，可手动刷新    |
| Docker 强隔离  | 工作台运行模式和状态栏   | 只有 daemon 与固定 digest 镜像都可用时才 ready |
| 知识检索       | 知识库顶部状态           | 显示检索模式、后端、片段数和降级原因           |
| Agent 工具     | AI Tutor 的 Agent 工具区 | 显示白名单、不可用原因和逐次审批要求           |
| 平台与数据库   | 设置 -> 能力             | 汇总运行环境、schema、quick check 和备份数量   |

静态 IPC 合同中的 `available` 只说明代码路径已经连接，不等于当前机器、Docker、Provider 或网络
真的 ready。能力页和各工作流探测共同提供运行时证据，不能用静态合同替代。

## 外部链接

应用只允许 `http:` 和 `https:` 外链交给系统默认浏览器。任何要求在 CodeHelper 主窗口中打开
远端页面的行为都不属于预期流程；相关残余风险见 [安全审计](../security-audit.md)。

## 应用菜单与窗口

标准菜单提供新建窗口、退出、撤销/重做、剪切/复制/粘贴、缩放、全屏和开发者工具等 Electron
命令。macOS 关闭全部窗口后应用保持运行；Windows/Linux 关闭全部窗口后退出。

窗口关闭前，主进程会请求 Renderer flush 工作区和练习草稿。若 SQLite 未完成但恢复区可用，
对话框会明确显示“仅保存在恢复区”；这不能当作数据库已经保存。

## 性能诊断

主进程每 5 分钟记录 IPC 调用汇总，每 2 分钟记录内存信息。`perf-get-ipc-stats` 诊断通道已暴露，
但当前没有统一 Renderer 状态页消费它。诊断日志可能包含内部通道名和路径，应在公开分享前检查。
