# 编辑器指南

CodeHelper 内置 CodeMirror 6 编辑器（@uiw/react-codemirror），提供专业的代码编辑体验。

## 概览

编辑器模块由以下组件构成：

- **CodeEditor** - 核心编辑器组件，基于 CodeMirror 6
- **EditorTabs** - 多标签页管理
- **Console** - 内置控制台面板，查看代码运行输出
- **TerminalPanel** - 终端面板集成

## 编辑器功能

### 语法高亮

CodeMirror 支持主流编程语言的语法高亮，包括但不限于：

| 语言       | 文件扩展名     |
| ---------- | -------------- |
| Python     | `.py`          |
| JavaScript | `.js`、`.jsx`  |
| TypeScript | `.ts`、`.tsx`  |
| C          | `.c`、`.h`     |
| C++        | `.cpp`、`.hpp` |
| Java       | `.java`        |
| C#         | `.cs`          |
| SQL        | `.sql`         |
| Markdown   | `.md`          |
| JSON       | `.json`        |
| HTML       | `.html`        |
| CSS        | `.css`         |

### 智能代码补全

- 基于语言上下文的智能提示
- 代码片段自动展开
- 参数信息提示
- 悬停信息展示

### 代码编辑特性

- **代码折叠** - 折叠/展开代码块（点击行号左侧的折叠箭头）
- **括号匹配** - 自动高亮匹配的括号
- **自动缩进** - 根据语言规则自动调整缩进
- **多光标编辑** - `Alt+Click` 添加多个光标同时编辑
- **块注释切换** - `Ctrl+/` 切换注释
- **代码格式化** - 自动调整代码格式
- **智能粘贴** - 粘贴代码时自动调整缩进

## 多标签页管理

### 标签页操作

| 操作               | 方式                   |
| ------------------ | ---------------------- |
| 新建标签页         | 通过题目详情或手动创建 |
| 切换标签页         | 点击标签页标题         |
| 关闭标签页         | 点击标签页右侧关闭按钮 |
| 重新打开关闭的标签 | 点击标签栏中的恢复按钮 |

### 标签页特性

- 每个标签页独立保存代码内容
- 标签页标题显示当前编辑的文件/题目名称
- 工作区底部状态栏会显示当前内容的保存状态
- 支持同时打开多个标签页并行编辑
- 工作区最多同时打开 50 个标签页；关闭的标签会保留在最近关闭列表中，重启应用后仍可点击标签栏的恢复按钮重新打开
- 编辑内容和切换语言会立即写入崩溃恢复日志；完整工作区快照保存失败时，内存内容和恢复日志都会保留，并在状态栏显示错误
- Electron 中的标签内容、语言、文件名、顺序、光标和滚动位置会同步到 SQLite；IPC 或数据库不可用时状态栏会明确显示“工作区仅本地保存”，不会把降级路径标成完整同步
- 题目 starter code 会等待 SQLite 工作区恢复完成，并且每次进入独立工作区只尝试初始化最初可见且真正为空的普通文件一次；之后新建的空白标签保持普通文件。欢迎示例、已有题目、练习标签、远端新版本或用户已有代码不会被首次加载和切换语言覆盖
- 关闭有待保存、失败或冲突状态的标签时会先显示针对该标签的确认。SQLite 重试仍失败时，标签保持打开；用户可以再明确选择“仅在本地关闭”，内容会进入最近关闭列表且状态继续标为降级
- 多窗口同时编辑同一标签时使用 revision/CAS 和重载前基线三方比较防止静默覆盖；双方都修改时必须进入冲突。每个窗口保留自己的当前选中标签，数据库中的 active tab 只作为下次启动提示，不参与内容 mutation generation。发生冲突时，工作区会显示目标文件、待处理数量和三项文字操作：采用数据库版本、保留本地写入新版本、另存本地副本
- 旧工作区升级不会把所有本地内容一律丢给数据库版本：明确的恢复区/仅本地内容，或基于相同数据库 revision 的编辑会安全重放；数据库 revision 已分叉时显示冲突；没有同步基线的普通旧快照不会静默覆盖 SQLite
- 多个窗口在 SQLite 不可用时分别编辑同一普通标签，重启不会只保留时间较新的一个窗口。相同内容会去重，不同内容会保留主标签并额外打开普通 `.recovered` 文件；即使两份内容已经写入 SQLite，恢复分支仍显示为待处理冲突并保留来源记录，直到用户明确选择采用数据库版本、保留本地版本或另存副本且操作成功。同一次应用启动中的窗口恢复区互相只读，旧启动的匹配记录要到 owner 已退出的下一次启动才清理；来源清理失败时冲突或降级提示会继续保留，不会先显示完整同步
- 损坏或不支持版本的本地快照会完整备份到 `.corrupt.*` 键；若只能打开默认工作区或部分恢复，顶部提示和状态栏会明确显示恢复降级，不会显示“已保存”
- 当前工作区快照格式为 v4。v1/v2/v3 快照会在原位置升级并保留标签、顺序、最近关闭、语言、光标和滚动位置；SQLite 编辑器 schema v1/v2 会在启动事务中升级为 v3，不需要删除 `codehelper.db`
- 如果检测到本地快照或恢复日志损坏，顶部会保持“工作区恢复降级”；即使 SQLite 能加载已有标签，也无法证明损坏记录中没有尚未同步的标签或视图，因此不会标成完整恢复
- 启动时会对 `codehelper.db` 执行 SQLite `quick_check`。确认主库损坏时，应用先逐字节隔离主库、WAL 和 SHM 为 `.corrupt.<timestamp>` 备份，再创建新库；全局恢复横幅会显示备份位置，编辑器随后从本地恢复区尝试找回尚未同步的内容
- 关闭应用窗口时会等待编辑器和当前练习草稿完成有界保存；如果 SQLite 失败但恢复副本有效，对话框会明确显示“内容仅保存在恢复区”，并说明下次启动可恢复，不会伪装成完整保存。恢复区也不可写或握手超时时，窗口保持打开并提供“返回应用”和“仍然关闭”选择
- Renderer 异常退出时，主进程会在同一应用实例内创建相同位置和尺寸的替代窗口，并显示“界面进程异常退出”横幅；该横幅不等于数据已写入 SQLite，仍应以底部“已保存 / 仅本地保存 / 恢复降级”状态为准。短时间连续崩溃超过 3 次会停止自动重载并要求用户选择
- 普通文件、题目和练习共用统一多标签拓扑（`kind: file | problem | exercise`）；标签栏会显示类型图标与“文件 / 题目 / 练习”标签
- 练习标签只保存拓扑与视图状态（文件名、语言、光标、滚动、排序）；**练习代码本身不以 `editor_tabs.content` 为权威**，而是走独立练习草稿 SQLite / recovery 流程。状态栏在练习模式下显示草稿同步/冲突/失败，不会伪装成完整工作区已保存

### 练习草稿恢复

- 打开练习时会创建或激活对应的 `exercise` 标签；代码与所选语言作为练习草稿自动保存，并在重新进入应用时恢复
- 练习标签可关闭、切换，并进入最近关闭列表；重启后可从恢复区与统一工作区快照恢复拓扑
- 保存使用数据库 revision 防止旧窗口或迟到请求覆盖更新内容
- 编辑后立即关闭窗口时，本地恢复区会保留尚未完成 IPC 写入的最新快照
- 检测到版本冲突时，状态栏会显示冲突，并提供“重新加载已保存草稿”和“保留本地草稿”两个操作
- 切换练习时会先保存旧题。若旧题只写入本地恢复区，新题打开后仍会显示“草稿仅本地保存”横幅和状态，直到该草稿真正写入 SQLite，不会用新题的干净状态掩盖降级
- 关闭练习标签时，只保存在恢复区或仍有版本冲突的草稿必须再次确认；这也包括切题后留在标签栏中的旧题。活动题会先强制保存，非活动题按各自保留的降级状态判断。确认框会区分“SQLite 未完成保存”和“版本冲突未处理”；数据库与恢复区都不可写时标签保持打开
- 恢复区达到 20 条或 1,000,000 字符总量时不会删除旧草稿来腾空间；新写入会显示容量错误。损坏的恢复 JSON 会先完整备份并停止覆盖；旧 v1 恢复数据的语法、结构或条目损坏时，原始内容会保存到跨重启稳定的 `.corrupt.<fingerprint>` 键并明确显示“恢复已降级”，有效兄弟条目仍可恢复，新编辑则写入独立 session
- 每个窗口使用独立的练习恢复区 session。重启时会聚合各窗口候选：内容与基线相同的候选去重，分叉内容显示冲突；未采用候选会保留为带窗口来源指纹的普通恢复文件，容量不足时也不会静默删除
- 某个窗口成功写入 SQLite 只清理与该次保存内容匹配的恢复副本，不会删除另一个窗口尚未合并的分叉草稿；同一 app boot 的其他窗口 session 不会被跨窗口改写，重启后才清理已无 owner 的匹配记录；旧的无 boot scope session 和 v1/v2 恢复数据仍会读取并安全迁移
- 从旧版快照恢复时，若练习标签仍内嵌代码，会把代码备份为本地恢复文件标签，并清空练习标签 content，避免草稿双写
- 旧版本只有 `exercise_id / title / code / updated_at` 的练习草稿表会在应用启动时原地升级；已有代码和时间戳保留，初始 revision 为 1，不需要先打开练习触发迁移
- 练习入口中的导入题目同样使用 `exercise-*` topology 和版本化草稿作为代码唯一权威；独立工作区题目不会被误归类为练习，也不会在升级时丢失
- 多窗口中另一个窗口关闭当前练习标签时，本窗口会先强制保存草稿。数据库保存成功或恢复区可用后才返回题库，并显示对应通知；两者都不可用时，本窗口保留标签和内存内容并提示不要关闭窗口
- 关闭最后一个练习标签会同时清除旧的练习入口恢复状态；因此切换主页面、重新进入练习或重启后仍停留在题库列表，不会自动重开刚关闭的标签。只有点击最近关闭或重新选择练习才会再次打开。恢复状态无法写入时，标签保持打开并显示错误，不会伪装关闭成功

## 控制台面板 (Console)

控制台面板位于编辑器下方，用于显示代码运行结果。

### 功能

- **标准输出 (stdout)** - 以绿色显示程序的正常输出
- **标准错误 (stderr)** - 以红色显示错误信息
- **退出码** - 显示程序的退出状态码
- **执行时间** - 显示代码运行耗时
- **编译阶段指示** - 对于 C/C++/C# 等编译型语言，区分编译错误和运行时错误

### 运行代码

1. 在编辑器中编写代码
2. 点击运行按钮或使用快捷键执行
3. 查看控制台面板中的输出结果

状态栏会显示当前语言的工具链探测结果：

| 状态     | 含义                                                  |
| -------- | ----------------------------------------------------- |
| 就绪     | 本机已找到对应解释器/编译器                           |
| 降级可用 | 可用但非首选路径（例如 C# 用 csc 而非 dotnet）        |
| 未就绪   | 缺少依赖；错误信息会附带安装建议，而不是只显示 ENOENT |

同时会标注 **本地受控运行（非强隔离）**：每次非 SQL 运行都进入一次性 Electron utility 进程，并限制超时、输出、并发与临时目录；本地受控**不是**完整沙箱，代码仍可能访问同用户文件与网络。

运行配置会同时显示“本地受控”和“强隔离”：

| 模式     | 说明                                                                                         |
| -------- | -------------------------------------------------------------------------------------------- |
| 本地受控 | 默认。utility + Job Object / ulimit；SQL 使用内置内存 SQLite                                 |
| 强隔离   | 需要本机 Docker 与已拉取的固定 digest 镜像。代码在无网络、只读根文件系统、非 root 容器中运行 |

Docker 不可用或镜像缺失时，“强隔离”保持禁用并给出原因，**不会**静默退回本地执行。SQL 不支持强隔离，请改用本地受控。题目或练习代码首次运行，以及代码改变后的首次运行，在本地受控模式下必须确认执行风险。

C# 优先使用 `dotnet` 临时项目；只有同时探测到 .NET SDK 时才标记为“就绪”，单独安装 .NET Runtime 不会被误报为可编译。不可用时再回退到 Windows `csc`，或 POSIX 的 `csc`/`mcs` 加 `mono` 兼容路径。工具链探测在后台异步执行，不阻塞应用主窗口。

Windows x64 安装包使用 Job Object 约束整棵非 SQL 运行进程树：最多 32 个进程、单进程内存上限 384 MB、整个 Job 内存上限 768 MB。若 Job Host 缺失、分配失败或未确认就绪，非 SQL 代码不会开始执行。macOS/Linux 的非 SQL 路径使用分语言的 `ulimit` 与进程组终止，属于尽力而为；Node 只有 V8 old-space 限制，dotnet 没有进程内存上限，均不提供严格 RSS、容器或 cgroup 边界。

这些限制只控制资源和生命周期。运行代码仍以当前用户身份执行，可以访问当前用户有权限访问的文件和网络；请只运行可信代码。

### 非 SQL 资源限制

非 SQL 代码运行器内置以下保护机制：

| 限制项       | 值          | 说明                              |
| ------------ | ----------- | --------------------------------- |
| 执行超时     | 10 秒       | 超时后自动终止运行进程树          |
| 输出大小     | 1 MB        | stdout/stderr 合计，超限终止      |
| 最大并发数   | 5 个        | 同时运行的请求上限                |
| 代码长度     | 100 KB      | 单次提交代码上限                  |
| 临时目录配额 | 50 MB / 轮  | 递归统计总量，扫描失败则终止      |
| 临时目录项数 | 20,000 / 轮 | 超出时按监控失败终止              |
| Windows Job  | 32 个进程   | 仅非 SQL；384 MB/进程，768 MB/Job |

SQL 使用独立的 SQLite utility 和内存数据库，不进入 Windows Job，也不使用非 SQL 临时目录配额。SQL 执行限制为 3 秒、256 KB 输入、100 条语句、1000 行结果、512 KB 格式化输出和 64 KB/单元格；SQLite 版本支持时还会尝试设置 128 MB `hard_heap_limit`。

## 提交代码到题库

在编辑器中编写的代码可以直接提交到题库系统进行自动判题：

1. 确保当前标签页关联了题目
2. 在控制台面板或题目详情中选择编程语言
3. 点击 **提交** 按钮
4. 系统自动运行所有测试用例并返回结果
5. 判题结果包括：通过 (Accepted)、答案错误、编译错误、运行时错误、超时
