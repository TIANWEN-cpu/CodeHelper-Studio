# Renderer to IPC channel contracts

This is the human-readable companion to `src/services/ipcContractMatrix.ts`. The TypeScript
matrix is canonical. Its automated test compares the matrix with the exported preload
allowlists as exact sets, walks the Electron source AST to find real invoke handlers and event
senders, and verifies that every cell in this table matches the executable contract.

Status meanings:

- `available`: implemented through the documented renderer and main-process path.
- `requires-environment`: implemented, but readiness depends on a provider, network, local
  toolchain, or another optional environment dependency.
- `degraded`: callable through a documented fallback, or the backend exists without a renderer
  entry. The row note in the executable matrix states the limitation.
- `placeholder`: callable, but the current result is empty or synthetic and must not be presented
  as the advertised advanced capability.

The preload column names the actual bridge method: `invoke` for request/response calls and `on`
for main-to-renderer events.

## Persistence test isolation

Electron E2E launches must set `CODEHELPER_E2E_USER_DATA` to a newly-created, absolute
temporary directory. `electron/main.ts` applies the override before `app.whenReady()`, so the
database, WAL files, local storage, cache, and other profile state stay outside the real user
profile. Relative paths and filesystem roots are rejected. Test harnesses must remove their
temporary directory after Electron exits.

Standalone Electron repository and utility smoke harnesses do not enter `electron/main.ts`.
They must call `createIsolatedElectronUserData()` before `app.whenReady()`, use a distinct
`codehelper-*-user-data-*` directory directly under the operating-system temporary directory,
assert that Electron selected neither its default profile nor the formal CodeHelper profile,
and remove only that prefix-guarded directory before exiting. This applies to the exercise-draft,
SQL utility, and code-runner utility audits.
